# ノードグラフと複数ビューの設計

## 目的と決定範囲

名前、本文、タグ、添付、進捗、日付を持つ共通ノードを、グラフ・ツリー・Finder・ガントから扱う。タスクとメモは利用目的を表す呼び方であり、排他的な種別や切替操作を設けない。本書は実装に先行する合意済みの設計である。実装の達成状況は末尾の受け入れ条件で確認する。

## 論理モデル

### ノード

ノードはワークスペース内で一意の不変IDを持つ。名前、本文、本文形式、タグ、添付、ステータス、開始日、期限、アーカイブ状態はノード自身の属性であり、どの配置先から編集しても同じ内容となる。プロジェクトも通常ノードとして扱い、プロジェクトをまたぐ関係を許容する。

ワークスペースには特別なルートノードを一つ置く。ルートは削除・移動・複製・アーカイブできず、親を持たない。通常ノードの自己接続と同じ親子対の重複は禁止する。

### 親子関係

親子関係は親ID・子IDで識別する有向辺である。子は複数の親を持てる。並び順は辺に属し、同じ子が異なる親の下で異なる順序を持てる。子同士を共有しても、親の名前や本文は共有しない。

複数ノードからなる循環は保存可能である。ルートから全ノードに到達できることを保証する。辺の削除やノード削除によって到達不能となったまとまりには、ルートからの入口となる辺を決定的に補う。到達不能な循環も対象とし、既存の循環を破壊しない。補われた関係は操作結果としてユーザーに通知する。

### ステータスの定義

| 意味 | 保存・API上の値 |
| --- | --- |
| 進捗管理を指定していない | ステータスを省略 |
| 進捗管理対象で、具体的な状態が未決定 | `Undefined`（明示値） |
| 未着手 | `Open` |
| 保留 | `Pending` |
| 進行中 | `In Progress` |
| 完了 | `Completed` |
| キャンセル | `Canceled` |

省略と明示的な未定義は区別する。既存データの省略を `Open` や `Undefined` へ自動変換しない。日付を付けてもステータスを自動付与しない。

## ビューの責務

| ビュー | 表示 | 構造編集の制約 |
| --- | --- | --- |
| グラフ | ノードは一つ、辺は実際の関係を表示。循環を含む | 循環を作る操作を許可。ルート保護、自己接続・重複禁止は維持 |
| ツリー | ルートから経路ごとに出現を表示。折りたたみは経路ごとに保持 | 新たな循環を作る辺追加・移動は禁止 |
| Finder | 選択経路を列で表示し、各列に同じ親の子を並べる | ツリーと同じ。現在の経路の祖先へ再進入しない |
| ガント | 日付・ステータスのあるノードを重複なく表示 | 日付・属性の編集。循環を作る構造編集は行わない |

ツリーとFinderでは現在の経路上の祖先へ到達した時点で展開を打ち切り、「循環参照」として表示する。参照は展開不可で、対象をグラフで表示する操作を提供する。別の枝に同じノードが現れることは許容する。保存された辺は打ち切りやフィルター、折りたたみによって失われない。

循環作成の判定はワークスペース全体の関係を参照する。移動では取り外す辺を除いた変更後の関係に対して判定する。既存の無関係な循環を理由に編集を拒否しない。

ツリーとFinderは親ごとの並び順を共有する。グラフの座標、ズーム、ビュー選択、選択経路、折りたたみは表示設定として保存し、ノード属性や親子関係とは区別する。グラフでノードをドラッグする操作は座標変更であり、関係は接続操作で編集する。

### ガントの表示条件

ルート以外で、ステータスが明示されているか、開始日または期限があるノードを対象とする。明示的な `Undefined` も含む。アーカイブは通常非表示とし、切替で閲覧できる。

- 開始日と期限がある場合は期間バーで示す。
- 日付が片方だけなら、その日付のマーカーで示す。存在しない期間を推測しない。
- ステータスだけなら「日付未設定」欄に示し、日付を割り当てられるようにする。
- 逆転する日付や不正な日付の入力は保存前に説明して拒否する。

## ノードと辺の操作

| 操作名 | 意味 |
| --- | --- |
| ここから外す | 現在の親からの辺だけを削除する。他の親と子孫の関係は残る |
| ここから移動 | 現在の親からの辺を移動先の親からの辺へ付け替える。他の親と子孫の関係は残る |
| 別の場所にも置く | 同じノードへ親を追加する。複製しない |
| ノードを削除 | ノード自身とその入出辺を削除する。子孫は削除しない |
| アーカイブ／復元 | ノード自身にのみ適用。子孫へ自動伝播しない |

移動に「子を含める」選択肢は設けない。子孫への関係が維持されるため、ツリー上では子孫も一緒に移動して見える。完了状態も親子へ自動伝播させない。

ツリー行とFinder項目のメニューは「ここ」の操作を中心とする。ノード自体の削除は共有先の親・直接の子への影響を提示する。循環で無限になる経路数を影響件数として表示しない。関係を外す通常操作は即実行と元に戻すで扱う。複数選択の一括操作も一回で取り消せる操作単位とする。

### コピーの三種類

| 操作名 | 新規ノード | 関係 |
| --- | --- | --- |
| ノードだけコピー | 対象ノード一つ | コピー先の親との辺のみ。子は付けない |
| 子を共有してコピー | 対象ノード一つ | 直接の子に新しい親としてコピーを追加。既存の子と子孫は共有 |
| 子孫ごとコピー | 対象から子方向へ到達するノード群 | コピー内部の辺と順序を再現。コピー元の外部の親との辺は引き継がない |

全方式で名前・本文・タグ・添付・ステータス・日付を保持し、新規IDを割り当てる。アーカイブ状態も内容とともに保持する。本文内の通常テキストリンクを書き換えることは初期仕様に含めない。ローカル画像・添付は元ノードの削除後もコピーから利用できるよう実体を確保する。

子孫コピーでは共有ノードを一回だけ作成し、内部の共有と循環を維持する。ルートはコピー対象から除外する。循環を含むコピーを新たに作成できるのはグラフからだけとし、他ビューでは理由とグラフへの導線を示す。

「子を共有してコピー」は直接の子の数に比例して辺を書き込む。孫以降の親情報は更新しない。UIで3方式の共有範囲を説明し、「コピー」の一語で意味を混同させない。

## 永続化と互換性

### 保存される実体

正本はワークスペース単位のノード集合と親子関係である。描画用のツリーを保存の正本にしない。グラフ操作は正本に対するコマンドとして実行し、全ビューが同じ確定状態を参照する。

### 物理実装の要件

初期実装は `<workspace>/.task-manage/graph-v1.json` を版付きの正本とする。ノード集合、親子関係、リビジョン、元に戻す／やり直しの情報を一つのスナップショットとして原子的に置き換える。画像と添付は `.task-manage/assets/<nodeId>/` に確保し、ノード削除だけでは履歴が参照する実体を削除しない。既存Markdownは初回移行時の入力として保護し、移行後の編集先は新しい正本に切り替える。

既存のプロジェクト別Markdownをそのまま正本にする方式は、プロジェクトをまたぐ一操作の途中失敗と取り消しで複数ファイルの整合性維持が必要になるため、初期実装では採用しない。この決定により、移行後に旧Markdownを外部編集しても新しい正本へ自動反映されない。旧APIからの更新と新APIからの更新を併存させず、旧画面の操作を新しい画面へ誘導する。

辺は子側の `parents: [{id, order}]` で保持できる。親から子を引く索引は再生成できる派生データとする。循環・子孫コピー・削除・到達性の処理は訪問済み集合を用い、終了を保証する。

書き込みはノードと関係を一貫した操作単位として扱う。失敗した保存を成功として画面に反映しない。元に戻す・やり直しは構造・本文・添付を含め、削除済みノードも復元可能にする。新しい操作を行った時点でやり直し履歴を破棄する。

### 既存形式との対応

| 既存の保存/API表現 | 論理モデルでの扱い |
| --- | --- |
| プロジェクト一覧の項目、`_project.md` | 通常のプロジェクトノード。特別なワークスペースルートの子 |
| `_index.md` のタスク | 共通ノード |
| 旧メモのMarkdownファイル | 親ノード配下の共通ノード |
| `WorkspaceTask` などの既存API名 | 共通ノードへの互換名。タスク種別を意味しない |
| 旧プロジェクト内の `parents` | ワークスペース全体のノードIDを参照する辺へ対応 |

移行時は元データとローカル画像・添付を保護する。重複IDや読めない本文を黙って統合・欠落させない。旧画面のツリー保存経路と新しい正本を同時に使って更新を失わないよう、移行後の編集経路を明確に切り替える。

## 実装分担と受け入れ条件

中核のデータ処理・永続化・操作履歴、複数ビューの統合、レビュー、実Electronの操作検証はSolが担当する。ガントと保存ストアの非同期制御はLunaが担当する。監督エージェントは担当範囲と契約を管理し、検証結果を統合する。担当間のAPIは型定義とIPC境界で共有し、同じファイルを同時編集しない。

実装のレビューでは、P0（データを欠落・破損させる問題）、P1（主要操作の意味や結果が設計と異なる問題）、P2（表示・操作性の問題）の順に解消する。型チェックの成功だけでは受け入れず、下記の動作と保存結果を検証する。

- [ ] 一つのルートから、複数プロジェクト・共有ノード・到達不能だった循環へ到達できる。
- [ ] グラフで作った循環が再起動後にも残り、ツリー／Finderで安全に打ち切られる。
- [ ] 非グラフビューからの循環作成、自己接続、重複辺、ルートへの破壊操作が拒否される。
- [ ] 移動・関係解除で他の親と子孫の関係が残る。
- [ ] 三種類のコピーでID・共有範囲・内部循環・ローカル画像・添付が正しい。
- [ ] 削除で子孫が消えず、到達性が修復され、取り消しで関係と内容が戻る。
- [ ] ステータス省略と明示的未定義が再読込後も区別される。
- [ ] ガントの期間・片側日付・日付未設定が表示され、日付を編集できる。
- [ ] 一つのビューでの編集が他ビューと再起動後に反映される。
- [ ] 保存失敗時にデータと操作履歴が矛盾せず、既存データが保持される。
- [ ] 型・lint・関連テスト・ビルドと、実Electronの操作・コンソール確認を完了する。
